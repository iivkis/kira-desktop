# Kira Lua UI Language — v0 draft

**Статус:** нормативный контракт для будущего этапа M1. **Компилятор пока не реализован.**
**Модель:** синтаксис Lua 5.4 → Rust-парсер → типизированный IR → генерация Rust/gtk4-rs и GTK CSS → rustc. Ни Lua VM при работе Shell, ни исполнение Lua во время генерации не допускаются.

## 1. Граница возможностей

Полный Lua с динамическими таблицами, метатаблицами, замыканиями и динамическими вызовами нельзя считать автоматически транслируемым в статически типизированный Rust. Kira использует **намеренно ограниченный Lua DSL**. Синтаксически корректный обычный Lua не обязательно является допустимым Kira UI.

`Widget`, `State`, `Style` и `Bind` — зарезервированные формы AST. Компилятор **не вызывает** одноимённые Lua-функции.

## 2. Единица компиляции M1

- Ровно один `return Widget { ... }` как корневое выражение; до него допускаются только комментарии и пробелы.
- Статическое дерево `children = { Widget { ... }, ... }`. Нет вычисляемых ключей, циклов, произвольных переменных, динамических таблиц и условий, конструирующих UI во время компиляции.
- Каждый Widget требует уникального строкового `id`, обязателен `kind`.
- Разрешены только `Box`, `Label` и `Button` (до расширения языка).
- `Box`: `orientation = "vertical" | "horizontal"`, `spacing = nonnegative integer`, `children`.
- `Label`: `text = string literal | Bind("field")`.
- `Button`: `text = string literal | Bind("field")`, необязательный `on_click`.
- Неизвестный `kind`, ключ, значение, event или выражение означает **ошибку компиляции**, а не fallback в Lua VM.

## 3. Типы, состояние и Bind

`state = State { count = 0 }` объявляет типизированные поля. Тип выводится только из литерала, доступного в исходнике. На M1 разрешены `i64` (целые Lua 5.4), `f64` (числа с дробной частью), `bool`, `String`. `nil`, таблицы, функции, сложные структуры, nullable types ещё не поддерживаются.

Состояние объявляется у Widget. Его дочерние виджеты видят поля предков. Дублирование имён state-полей на любом вложенном уровне M1 запрещено, чтобы не создавать неоднозначные ссылки.

`Bind("count")` ищет поле State в этой области видимости. Для `text` поддерживаются только `String` и особое преобразование `i64` в десятичный текст. Универсального динамического `toString` нет. Binding компилируется в зависимость на GTK property: изменение поля обновляет все связанные подписи в том же GTK main context.

Арифметика `i64` использует **явные wrapping-операции Rust**, соответствующие целочисленному wraparound Lua 5.4. Поведение одинаково в debug/release. Несовпадения типов отклоняются статически.

## 4. Обработчики событий

```lua
on_click = function(state)
  state.count = state.count + 1
end
```

Это узел синтаксического дерева, а **не исполняемая Lua-функция**. Разрешён ровно один параметр `state`, выражения с литералами/известными полями, совместимые арифметические операции `i64`, присваивания объявленным полям и `if` с `bool` условием. На M1 запрещены произвольные вызовы функций, upvalues, циклы, корутины, импорт и произвольные side effects.

При сигнале GTK `clicked` сгенерированный Rust обновляет state и синхронизирует связанные GTK properties. Весь GTK UI и состояние принадлежат main context. Параллельные системные источники позже подключаются типизированными сообщениями.

## 5. GTK-стили, не web CSS

`Style { ... }` порождает классы и разрешённые CSS-объявления для **GTK4 CssProvider**. Свободный CSS, селекторы, внешний CSS-файл и HTML-layout **не разрешены** в M1.

| Lua field | GTK CSS | Тип |
| --- | --- | --- |
| `background` | `background-color` | Цвет Kira Default |
| `color` | `color` | Цвет Kira Default |
| `padding` | `padding: Npx` | Целое неотрицательное значение |

Для M1 цвета ограничены пятью каноническими `#000000`, `#14213d`, `#fca311`, `#e5e5e5`, `#ffffff` и их `#RRGGBBff` вариантами. `orientation` и `spacing` — свойства **gtk::Box**, не CSS.

Классы генерируются с детерминированным безопасным именем и назначаются соответствующему native widget. Нельзя интерполировать произвольную строку Lua в Rust-код, selector или CSS. GTK4 CSS не совпадает с браузерным CSS.

## 6. Граница доверия и безопасность

- Парсер читает Lua как **недоверенный текст** и никогда его не выполняет. Запрещены `require`, `load`, `dofile`, `os`, `io`, `debug`, `_G`, metatables, FFI и доступ к файловой системе/сети.
- Пайплайн строго последовательный: **Parser → AST со span → schema/name/type validation → typed IR → codegen**.
- Сгенерированный Rust содержит только разрешённые вызовы gtk4-rs и проверенных Rust helper API. Системные полномочия, D-Bus и Niri действия не попадают в руки Lua напрямую.
- **Сгенерированный бинарник запускается с правами Shell.** Запрет запуска Lua во время работы не эквивалентен sandbox. По этой причине качество валидации и codegen критично.

## 7. Воспроизводимая сборка

- Явный entry file, зависимости и build directory. На M1 нет Lua импортов и внешних Lua модулей.
- Генерация `generated_ui.rs` и `generated_ui.css` внутри игнорируемой директории сборки (например, Cargo `OUT_DIR`); не переписывать ручные `src/*.rs`.
- Побайтово идентичный результат на одинаковом исходнике и версии компилятора. Никаких timestamps, случайных ID и абсолютных путей в генерируемых файлах.
- Диагностика `file:line:column: error-code: explanation`, ограничения размеров/depth, негативные тесты и fuzz/property-проверки.
- Без сетевых обращений и загрузки неприкреплённых источников при Cargo/Nix сборке.
- Интеграционный тест запускает нативный counter в GTK, проверяет текст до/после клика и отсутствие Lua VM/WebKit в целевом UI.

## 8. Канонический M1 acceptance fixture

[examples/v2/counter.lua](../examples/v2/counter.lua) описывает вертикальный `gtk::Box`, `gtk::Label`, `gtk::Button`, локальное поле `count: i64`, изменение `state.count` при клике, обновление связанной метки и нативные GTK CSS стили.

**Это требование к будущему компилятору, а не работающий сегодня API.**
