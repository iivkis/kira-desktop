# Kira UI · reusable GTK4 component library

**Normative for native-gtk. First build the reusable UI library, then build Kira Desktop from it.** This is a hard sequencing rule, not a later cleanup task.

This library's ongoing design/motion review and enforceable source-only
invariants are documented in [NATIVE_DESIGN_MOTION_REVIEW.md](NATIVE_DESIGN_MOTION_REVIEW.md).
A fast green CI run is not graphical acceptance.

## Architectural boundaries

- `crates/kira-ui` is a reusable GTK4/gtk4-layer-shell library. It owns public view models, native controls, shared CSS, accessibility and popup lifecycle. It can be embedded in another GTK application without Core, Niri, IPC, filesystem writes or privileged commands.
- `crates/kira-services` owns pure Linux system models and trusted native adapters; no GTK or WebKit dependency. Existing tested native policies belong here rather than being deleted with their former WebKit presentation.
- `crates/kira-shell` is the **Kira Desktop composition root**. It translates typed Core snapshots and GIO discovery into `kira-ui` view models, routes callbacks through approved services and starts the application. It must not become another UI component framework.

## Required implementation sequence

1. **Design the reusable component's API:** input view model, events/intents, lifecycle, empty/offline/error states and keyboard/a11y contract. Do not use raw IPC messages, Niri commands or shell strings in the public interface.
2. **Implement in kira-ui:** build the GTK widget tree, visual styles, focus behavior and bounds. It must work without launching Kira Core.
3. **Test the library independently:** cover pure selection, filtering, geometry and state transitions in Rust tests. UI smoke/visual acceptance remains separate from headless tests.
4. **Connect trusted services:** system discovery, launch, metrics, display transactions and notification policies run outside GTK main-thread blocking paths and deliver owned data.
5. **Compose Kira Desktop:** use tested library components from `kira-shell`, translating only typed state and intents. No copy-paste widget implementation.
6. **Accept on Wayland:** run nested Niri, check multiscreen focus/geometry/scaling, a11y, keyboard operation and packaged `nix build .#default`.

## Launcher catalogue identity safety

The Shell now removes duplicate GIO application IDs globally after display-name sorting (not only adjacent IDs). The reusable Launcher independently filters duplicate IDs after search ranking, including an empty query. This keeps keyed GTK rows unique even if a trusted catalogue supplies repeated identities, while preserving distinct applications that share a display name. Pure Rust regression tests cover both boundaries; packaged GTK and nested-Niri acceptance remain unverified.

## Guardrails and acceptance

No WebKit fallback, browser runtime, direct shell execution or arbitrary command execution in UI. Component callbacks express intent only. Kira UI stays independent of the actual compositor and Core transport. Native does not mean secure plugin isolation; third-party native widgets remain out of scope.

The opt-in `scripts/accept_nested.py` now coordinates a fresh private D-Bus, disposable nested Niri, real SNI fixture, real notification calls and CRC-validated timestamped grim evidence plus an offline unreviewed review index; headless CI only exercises the fail-closed environment and protocol tests, not graphical source parity.

The native System Monitor and DisplaySettings GTK views are now wired to their existing Rust services, but **passing headless Cargo tests does not demonstrate real Niri display transactions or visual parity**. See [ACCEPTANCE_NATIVE_G2.md](ACCEPTANCE_NATIVE_G2.md) for mandatory nested graphical scenarios. Deep StatusNotifier menu behavior, native notification presentation QA, multi-output popup positioning, detached windows, source-complete TENET animations, richer launcher performance and packaged Niri smoke remain explicit work.

**Live-output safety gate:** `kira-shell` disables Apply/Confirm/Save outside the controlled nested preview. A 15s worker timeout survives GTK main-thread stalls, but not termination of the entire Shell process. Before enabling production display changes, move the watchdog to Core or a separate supervisor and test process-death rollback. Setting `KIRA_PREVIEW` manually is **not** a security boundary; use only the verified nested preview script.

## G3 increment: native in-bar warning inspector

- `kira-ui::WarningInspector` implements the source's in-bar, 42px full-width inspection mode. It keeps stable warning IDs while faults appear/disappear; Next advances one item and wraps, and dismiss restores the warning button or local clock focus. A read-only selectable GTK text view allows copying long errors without an extra Wayland surface. Tab/Shift+Tab remain inside the inspector and Escape closes it. It bounds incoming text and deduplicates IDs; no raw HTML or privileged capability enters `kira-ui`.
- `kira-shell` now forwards **only genuine** KDL reload diagnostics, failed workspace focus RPC responses, GIO launch errors and process scan errors. Failed workspace RPC calls no longer disappear into stderr; the operation stays pending until its result arrives, native workspace controls become insensitive immediately, and Niri's EventStream alone determines the selected workspace. Successful retries clear their own previous warning, and clearing the last warning closes the inspector rather than reviving it when another appears.
- The inspector uses the same 42px Top Bar GTK Overlay, not a second transient layer-shell window. The Top Bar requests on-demand Wayland keyboard interactivity rather than exclusive focus so Tab/Escape in the inspector can be delivered after explicit user activation. This restores a substantial missing interaction from frozen main; exact layout/focus and paired native screenshot evidence still need nested-Niri review. No parity flag is changed by tests alone.
