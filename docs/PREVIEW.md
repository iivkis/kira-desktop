# Безопасный preview Kira Desktop во вложенном Niri

Команда **`task dev:preview`** запускает экспериментальный Kira Desktop внутри
отдельного окна Niri, не заменяя текущую оболочку NixOS.

## Запуск

Из уже работающего графического сеанса Wayland:

```sh
git pull
nix develop --command task dev:preview
```

По умолчанию команда устанавливает frontend-зависимости только при изменении
`frontend/package-lock.json`, запускает Vite и делает **инкрементальную
debug-сборку Cargo** в `target/debug`. Это быстрее повторного
`nix build` после правки Rust или Svelte. Первый запуск по-прежнему может
потребовать полной компиляции Rust-зависимостей WebKitGTK.

Для проверки именно установочного Nix-пакета используется отдельная команда:

```sh
nix develop --command task dev:preview:release
```

Если исходники и frontend уже собраны, можно открыть существующий preview
без вызова Cargo и Vite:

```sh
nix develop --command task dev:preview:run
```

Команда запускает три процесса:
**вложенный Niri, Kira Core и Kira Shell**. Дисплей вложенного Niri определяется
автоматически через его `spawn-at-startup`: выбирать `wayland-1` или
`wayland-2` самостоятельно не требуется.

Когда всё готово, в терминале появится:

```text
[preview] Nested display: wayland-N; parent: wayland-M
[preview] Kira running inside nested Niri. Ctrl+C to exit.
```

Имена дисплеев зависят от системы. Это пример вывода, не обещание точного значения.

## Как закрыть

- **Ctrl+C** в терминале, где запущен Taskfile.
- **Alt+Shift+Q** внутри окна вложенного Niri.
- Закрытие окна вложенного Niri, если это поддерживает текущий внешний композитор.

При завершении уничтожаются **только процессы этого preview** и временный каталог.
Команда не вызывает `nixos-rebuild switch`, `systemctl`, `pkill`,
не изменяет `~/.config/niri/config.kdl` и не трогает пользовательские службы.

## Почему это безопаснее прямого запуска

- Отдельная временная конфигурация Niri без автозапуска пользовательской панели.
- Никакого `niri --session`, который может менять окружение системных сервисов.
- Дисплей проверяется: Shell не стартует, если Niri вернул сокет основного Wayland.
- Переменная `KIRA_CORE_SOCKET` размещает IPC в приватном временном каталоге,
  не конфликтуя с основным `$XDG_RUNTIME_DIR/kira-desktop.sock`.
- `KIRA_PREVIEW=1` запрещает GTK-приложению активировать одноимённую
  Shell-сессию за пределами превью.
- Все дочерние процессы управляются по PID/группе; глобальное завершение
  процессов по имени запрещено.

Текущая реализация всё же использует **ту же учётную запись пользователя,
D-Bus-сеанс и Linux-систему**, что и основная оболочка. Это не полноценная
изолированная виртуальная машина и не защита от недоверенных расширений.
Для полной изоляции используйте NixOS VM.

## Проверки и диагностика

```sh
nix develop --command task dev:preview:test
python3 scripts/dev_preview.py --validate-config  # внутри nix develop
nix build
```

CI проверяет сценарий на имитированных Niri/Core/Shell без дисплея. Это
проверяет управление процессами, перенаправление Wayland и cleanup, но **не**
заменяет визуальный тест настоящего GTK4/WebKitGTK в Niri.

Если вложенный Niri или Shell аварийно завершится, скрипт напечатает последние
строки временных логов, а затем удалит временный каталог.

Если `WAYLAND_DISPLAY` или `XDG_RUNTIME_DIR` отсутствуют, команда
откажется стартовать, чтобы не запустить панель непредсказуемо.

## Если вместо интерфейса видна только чёрная полоса

В ранних версиях Svelte собирался как ES-модуль и загружался WebKitGTK через
`file://`. Для модульных JavaScript-файлов такой способ может блокироваться
политикой CORS, даже если GTK-поверхность уже появилась.

Shell теперь предоставляет **локальный протокол `kira-ui://app/`** и отдаёт
файлы собранного интерфейса через WebKit без открытия HTTP-порта и без
глобального доступа к `file://`. Путь проверяется и не может выходить из
каталога UI. При ошибке отображается заметное сообщение-заглушка, а в логах
появляются `kira-shell: UI asset denied`, `kira-shell: WebKit load failed`
или `kira-shell: UI rendering check failed`.

Для проверки обновить исходники и пересобрать:

```sh
git pull
nix develop --command task dev:preview
```

Ожидаемый результат: **K**, рабочие пространства 1–3, **Kira Desktop**,
состояние Core и часы. Простая чёрная полоса без текста уже не считается
успешным запуском.
