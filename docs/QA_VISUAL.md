# Этап 0: Visual QA и packaged Shell smoke test

**Статус:** автоматизация и шаблон проверки подготовлены; фактические скриншоты
Niri/WebKit на машине разработчика и визуальная приёмка **ещё не получены**.
Issue: [#10](https://github.com/iivkis/kira-desktop/issues/10).

## Прогон на NixOS

Из **существующей пользовательской сессии Wayland** (не из SSH,
не из headless CI, не через `nixos-rebuild switch`):

```sh
nix develop --command task qa:visual:release
```

Эта команда:

1. Собирает настоящий пакет `nix build .#default` из lock-файлов.
2. Запускает **вложенный оконный Niri** с собственными
   `WAYLAND_DISPLAY`, `NIRI_SOCKET`, `KIRA_CORE_SOCKET`.
3. Ждёт фактических сообщений `Svelte entrypoint mounted` и
   `Svelte panel DOM verified` от WebKit, отправляет настоящий
   `get_state` Core через Unix socket и проверяет ответ.
4. Проверяет, что `NIRI_SOCKET` существует и **не равен** сокету
   родительского Niri, затем переключает масштаб **только вложенного**
   output на 100%, 125%, 150% и 200%.
5. При каждом масштабе снимает **сам экран вложенного Niri** через его
   `niri msg action screenshot-screen --path` и проверяет PNG.
6. Записывает четыре PNG и `manifest.json` в
   `artifacts/visual-qa/<timestamp>-<pid>/`, останавливает только
   процессы preview и очищает временную конфигурацию.

Для быстрой проверки без пересборки Nix-пакета:

```sh
nix develop --command task qa:visual:fast
```

Режим `fast` использует Cargo debug и production Vite HTML, **не**
подтверждает работоспособность установочного Nix-пакета.

**Важно:** каждое выполнение создаёт новую папку. Артефакты игнорируются Git,
чтобы не загрузить случайно содержимое экрана в публичный репозиторий.
Скриншоты относятся к изолированному Niri, не к хостовому рабочему столу.
Если автоматический кадр/масштаб недоступен в конкретной версии Niri,
команда завершится с ошибкой, а в `manifest.json` будет `"status": "failed"`.
Не отмечайте тест успешным только потому, что `nix build` прошёл.

## Ручной визуальный просмотр (обязателен)

После capture открыть **все четыре PNG** и проверить:

- Полоса Top Bar закреплена на верхнем крае, имеет ожидаемую высоту
  42 логических пикселя, без разрывов, прозрачных/пустых областей и обрезки.
- KIRA, preview-рабочие пространства, центральный заголовок,
  **CORE Online** и часы видны и не перекрываются.
- На 125% и 150% текст, линии и границы не становятся заметно размытыми;
  отсутствуют дробные щели между WebKit и layer-shell поверхностью.
- Тема использует канонические пять цветов и остаётся читабельной,
  выбранное workspace отличается не только цветом.
- Отдельно запустить `nix develop --command task dev:preview`,
  изменить **ширину окна вложенного Niri** примерно до 800, 1024 и
  1280 физических пикселей и проверить узкую полосу/адаптивность.
  Это **ручная** часть; смена scale сама по себе не доказывает работу
  на всех ширинах.
- Проверить `task dev:preview:debug` при неполадках: диагностические
  строки WebKit, ошибки UI, Core или Wayland.
- Закрыть вложенный Niri и убедиться, что исходная графическая сессия
  не нарушена, `~/.config/niri` и системные службы не изменены.

Все обнаруженные баги оформлять отдельными GitHub Issues со ссылкой на
версию, scale/ширину, описание ожидаемого/фактического поведения и
**обезличенные** скриншоты по необходимости.

## Отчёт о прогоне

В `manifest.json` автоматически пишутся сборка, Core response,
имя виртуального монитора, фактическая геометрия, масштаб, PNG-хеш
и `status: captured_review_pending` после успешной записи скриншотов.
Эта запись **не** является визуальным approval.

Для закрытия Этапа 0 в Issue #10 нужно явно зафиксировать:

| Проверка | Результат до реального прогона |
| --- | --- |
| Предыдущие CI / native Nix build | Было успешно в истории проекта |
| Packaged Nix smoke в новой QA-сессии | Не запускался локально |
| Скриншоты 100 / 125 / 150 / 200% | Нет |
| Ручной просмотр всех четырёх кадров | Не выполнен |
| Ручные размеры окна 800 / 1024 / 1280 | Не выполнено |
| Проверка завершения preview без побочных эффектов | Есть mock-тесты; нужен локальный прогон |

Финальный вердикт: **PASS** только если авто-отчёт успешен и ручной
визуальный просмотр подтверждён. В противном случае: **BLOCKED** или **FAIL**.

## Автоматические тесты в CI

`tests/test_qa_visual.py` проверяет отказ при отсутствии/подмене
Niri socket, наличие подтверждения DOM, корректность Core JSON-RPC,
одиночный виртуальный output, четыре кадра и отчёт об ошибке.
Это мок-тесты, они **не подменяют** реальную GTK/WebKit/Niri отрисовку.

Документация по безопасному preview: [PREVIEW.md](PREVIEW.md).
