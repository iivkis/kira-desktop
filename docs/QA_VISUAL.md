**Статус:** пользователь успешно запустил предыдущую QA-команду дважды
(2026-11-01: каталоги `20261101-004226-83233` и `20261101-004330-83927`).
По предоставленным логам Nix-пакет собран, автоматический захват завершён и
дочерние процессы остановлены. **Сами PNG не были просмотрены, поэтому
визуальная приёмка остаётся открытой.** Задача: [#10](https://github.com/iivkis/kira-desktop/issues/10).

## Безопасная проверка по умолчанию: без скриншотов

Из существующей графической Wayland-сессии на NixOS:

```sh
nix develop --command task qa:visual:release
```

Команда собирает `nix build .#default`, запускает отдельный оконный Niri,
Core и Shell, дожидается `Svelte entrypoint mounted` и
`Svelte panel DOM verified`, отправляет настоящий `get_state` в Core
через отдельный Unix socket и запрашивает список виртуальных выходов Niri.
После проверки завершает только собственные дочерние процессы.

**Важно:** `qa:visual:release` теперь **не переключает масштабы, не делает
скриншотов, не сохраняет PNG и не копирует ничего в буфер обмена**. Это
проверка работоспособности, а не полноценная визуальная приёмка.

Быстрый вариант (Cargo debug, не проверяет поставляемый Nix-пакет):

```sh
nix develop --command task qa:visual:fast
```

## Снимки экрана: только явный выбор

Для проверки масштабов пользователь **отдельно** запускает:

```sh
nix develop --command task qa:visual:capture:release
```

Для Cargo debug:

```sh
nix develop --command task qa:visual:capture:fast
```

Только эти команды временно меняют масштаб **вложенного** Niri на
100%, 125%, 150% и 200%, записывая по одному PNG на каждом уровне в
`artifacts/visual-qa/<timestamp>-<pid>/`.

Снимки снимаются `grim -o <nested-output> <file>`, работающим через
дочерний `WAYLAND_DISPLAY` с поддержкой `wlr-screencopy`. В отличие от
встроенной команды `niri msg action screenshot-screen`, **grim не
копирует снимок в буфер обмена**. `grim` присутствует в `nix develop`;
при его отсутствии захват завершится ошибкой, без скрытого возврата к
команде Niri, копирующей картинку.

Вместе с PNG сохраняется `manifest.json` (Core, масштаб, разрешение,
SHA-256, `captured_review_pending`). Скриншоты **не выгружаются в GitHub**
и каталог `artifacts/visual-qa/` добавлен в `.gitignore`.
Снимки относятся к изолированному Niri; основная графическая сессия и
конфигурация `~/.config/niri` не меняются.

**Предыдущая версия QA**, запущенная 1 ноября 2026, применяла
`niri msg action screenshot-screen`. Эта команда Niri также копирует
снимок в буфер обмена, что было неожиданным побочным эффектом.
Для новых запусков такое поведение устранено.

## Ручная визуальная приёмка

После явного захвата скриншотов открыть все PNG и проверить:

- Top Bar на верхнем крае, высота 42 логических пикселя, нет обрезанных
  областей, пустых полос и смещений.
- Верхняя панель занимает ровно 42 px: слева синяя зона KIRA с оранжевой
  меткой, в центре чёрная рабочая область, справа более спокойная системная
  область. Нижняя цветная линия не добавляет высоты.
- Выбранное рабочее пространство выделено оранжевым блоком, а остальные
  состояния различимы; нет отдельных тяжёлых рамок или теней у кнопок.
- Справа один вертикально центрированный ряд: READY/STARTING/CORE OFF/
  NIRI OFF, тонкий разделитель и часы. Отдельных заголовков SYSTEM/LOCAL
  больше нет, статус Core не проваливается вниз относительно часов.
- READY показывается только когда Core и Niri подключены; при отсутствии
  Core/Niri виден конкретный текст ошибки. Подсказка статуса содержит версию
  Core и состояние Niri, а подсказка часов — полную дату.
- При ширине до 540 px здоровая подпись READY скрывается, точка и часы
  остаются, но сообщения об ошибках не скрываются.
- В таб-навигации видно фокус как на выбранном workspace, так и на обычном;
  active/urgent и отключённый Core остаются различимыми.
- На дробных масштабах нет заметного размытия или дробных щелей.
- Цвета соответствуют Kira Default, фокус и выбранное пространство
  различимы не только цветом.
- Дополнительно **вручную** открыть `task dev:preview` и проверить
  узкие и широкие размеры окна (ориентиры 800/1024/1280 пикселей).
  Скриншоты разных scale **не равны** проверке разных ширин.
- Открыть Launcher через кнопку KIRA: проверить чёрный редакционный
  заголовок, синюю рабочую зону, тёмное поле поиска, иконки, боковую
  оранжевую метку выделения, подсказки клавиш, Esc/↑/↓/Enter и ошибку
  запуска. Оранжевый не должен заливать всю строку. Проверить также,
  что окно не резервирует дополнительное место на экране.
- Нажать на часы: проверить отдельное окно под правым краем Top Bar
  без дополнительной резервации экранного пространства, с текущим временем,
  датой и локальным часовым поясом. Часы внутри обновляются каждую секунду.
- Проверить переключение месяцев и годов, выбор любого дня, ISO-неделю и
  номер дня года. TODAY возвращает сегодня; COPY YYYY-MM-DD копирует
  именно выбранную дату и меняет подпись на COPIED. Проверить Escape,
  повторный клик по часам, закрытие при потере фокуса, взаимодействие с
  Launcher, Tab/focus и узкий монитор.
- После завершения убедиться, что основные приложения Niri не были
  затронуты и остались запущены.

При дефектах оформить отдельный Issue с масштабом, шириной, ожидаемым
результатом и обезличенным кадром (если нужен). **CI и успешный
`manifest.json` не заменяют визуального просмотра.**

контракт Core `get_state` с мок-сервером, ожидание Svelte DOM,
read-only smoke без изменения масштаба и без скриншотов, четыре масштаба
только в режиме capture, `grim` без clipboard, PNG и честный
