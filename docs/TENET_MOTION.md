# TENET Motion System · Kira Desktop

**Статус: обязательный стандарт motion design.** Действует для **любой новой или изменяемой анимации** Kira Desktop: Svelte/WebKit-виджетов, элементов Top Bar, Launcher, Calendar, System Monitor и будущих поверхностей. При обновлении существующей анимации её нужно привести к этому стандарту. Полная переработка всех уже существующих эффектов — отдельная задача, а не повод ломать работающий интерфейс без проверки.

**Источник концепции:** авторское проектное правило, вдохновлённое логикой времени и причинности фильма *Tenet* («Довод», 2020), **не** копирование его VFX, цветовой схемы, графики, персонажей или звука.

## Главная идея

> Обычная анимация: **действие → движение → результат**.
>
> TENET-анимация: **результат → обратное движение → причина**, пока остальная часть интерфейса может продолжать двигаться вперёд.

**Инверсия — это порядок событий, а не просто отрицательная скорость, отражённая ось или `animation-direction: reverse`.** В одной сцене могут сосуществовать прямые и инвертированные временные потоки, объединённые одним событием и общими координатами контакта.

## Пять обязательных законов

| Закон | Требование |
| --- | --- |
| **01 · Reverse Causality** | Следствие *может* визуально предшествовать причине; причина реального действия пользователя не подменяется. |
| **02 · Dual Time Flow** | В одной сцене допустимы независимые потоки **FORWARD (+1)** и **INVERTED (−1)**, синхронизированные общим временем. |
| **03 · Physical Continuity** | Обратный ход сохраняет тот же путь и профиль скорости, инерции, вращения, деформаций и отскоков. |
| **04 · Temporal Memory** | Состояние и траектории одной сцены фиксируются и могут быть воспроизведены с любой временной перспективы. |
| **05 · Causal Consistency** | После завершения/отмены все элементы оказываются в точном, ожидаемом состоянии без визуального скачка и утечки эффекта. |

**Важно:** правила относятся и к обычной анимации. Простые состояния и микроотклики могут оставаться FORWARD, если причинность, непрерывность и доступность соблюдены. Инвертировать *всё* запрещено. Ориентир **70–80% привычного движения** и **20–30% выразительных инверсий** — дизайнерская эвристика, **не** автоматическая квота.

### Обязательное качество: перетекание и упругость

**Анимация TENET обязана быть непрерывной, направленной и физически отзывчивой.** Если объект меняет расположение, размер, выбранное состояние или визуальный акцент, он *движется из своего текущего отрисованного положения* в следующее. Нельзя заменять его двумя элементами, которые попеременно исчезают/появляются. Например, в System Monitor **один** оранжевый индикатор перетекает под другую вкладку; переключение двух `border-bottom` запрещено.

- **Shared element / continuity.** Сохранять идентичность визуального маркера при переходе (один DOM-элемент, измеренная геометрия, FLIP/GSAP). При смене цели посреди анимации перенаправлять текущий tween через `overwrite: 'auto'` без возврата в старое начало.
- **Elastic landing.** У движущегося элемента есть ускорение, замедление и *сдержанное* пружинящее завершение, а не монотонная «ползучая» поступь. Для акцентных перемещений подходят настроенные `back.out(1.1–1.3)` или эквивалентные физические профили. Упругость не означает хаотичную тряску, бесконечный bounce и перерегулирование прозрачности. Для opacity выбирать отдельный монотонный easing.
- **Tempo.** Popup TENET master теперь работает в 1.2× прежней скорости: внешнее раскрытие/закрытие занимает примерно 450 мс вместо 540 мс, упругая сборка секций ~367 мс вместо 440 мс. Native fade — 133 мс вместо 160 мс; перемещение индикатора около 420 мс, отклик новой панели около 300 мс. Это **отправные профили**, не глобальная задержка реальных действий. Длительные `sine.inOut`-въезды целых виджетов не соответствуют характеру Kira.
- **One event, one trajectory.** При повторном клике, смене вкладки, resize, Escape или закрытии незавершённое движение немедленно принимает новую корректную цель. Для INVERTED событий запоминается исходная история, как предписано законами выше; обычный FORWARD-переход вкладок не нужно искусственно инвертировать.
- **Visual truth.** Тексты, ARIA, данные, фокус и клики обновляются сразу. Подвижны только визуальные слои, а не настоящая выборка метрик. Прозрачность не должна скрывать важный контент, размеры окна не должны анимироваться и создавать обратную связь с WebKit resize.
- **Motion budget.** Предпочитать transform/opacity на 1–3 поверхностях, не анимировать множество вложенных ECharts-графиков, не создавать JS-цикл поиска геометрии на каждом кадре. Под `prefers-reduced-motion` выставлять точную конечную геометрию и мгновенно останавливать обе стороны native/WebKit.

Любой новый tabs, segmented control, selection underline, carousel thumb, active row, expandable rail и другой *перемещающийся* указатель должен иметь **один физически сохраняемый маркер** с прерываемым GSAP-переходом. Исключения для дискретных состояний (нет общего объекта для интерполяции) нужно обосновать; мгновенная замена содержимого допустима, но новая панель входит коротко и непрерывно, без фальшивого «сдвига» показаний.

## I. Шестнадцать правил

### Фундамент движения

1. **Собственное направление времени.** У каждого объекта есть направление FORWARD (+1) или INVERTED (−1) и собственная последовательность событий. INVERTED ≠ «влево» и ≠ просто `reverse` CSS-анимации.
2. **Причина и следствие.** Для инверсии последовательность «удар → трещина → осколки» превращается в «осколки → восстановление трещины → обратный удар». Не изображать несуществовавшие пользовательские действия.
3. **Сосуществование потоков.** Фон и функциональная надпись могут двигаться вперёд, а следы, частицы и фрагменты — восстанавливаться в обратном порядке на *той же* сцене.
4. **Обратная причинность с целью.** У каждого возвращаемого фрагмента есть конкретные исходные координаты, угол и размер, а не приблизительный случайный центр.
5. **Инверсия полного профиля.** Оборачивается траектория **вместе** со скоростью, easing, инерцией, вращением, деформацией, отскоком и вторичными колебаниями; не ограничиваться переменой знака `x`.
6. **Разрушение/восстановление.** Если эффект разъединяет целое на части, обратная сцена восстанавливает именно те же части, без генерации новых осколков.
7. **Возвращение к источнику.** Волны, маски и следы могут сходиться к исходному объекту или реальным координатам активации вместо расходящегося CSS ripple.
8. **Временная память.** Один интерактивный эпизод записывает начальное состояние, траектории, случайный seed/параметры и точку столкновения; повтор в обратную сторону воспроизводит *тот же* эпизод.
9. **Замкнутая согласованность.** Цикл может быть **A → B → C → B → A**, но финальные transform, opacity, геометрия, фокус и значение должны совпадать с корректным состоянием интерфейса.
10. **Вторичные последствия.** Свет, пыль, частицы, шлейфы, контуры, маски и деформации тоже участвуют в логике инверсии; не оставлять «призраков» после возврата.

### Взаимодействие временных потоков

11. **Общая точка контакта.** Прямые и инвертированные потоки сходятся в реальных координатах одного события: клик, касание, выбранный элемент, координата курсора.
12. **Переключение — событие.** Смена направления времени должна иметь понятный триггер (например, специальный режим или повторное открытие), а не быть случайным зеркальным отражением.
13. **Две перспективы на одну сцену.** Сцену можно мысленно или технически просмотреть вперёд и назад: обе версии сохраняют одни состояния и точки взаимодействия.
14. **Схождение потоков.** Две группы объектов могут идти с противоположных концов временной шкалы и встретиться на одном ключевом кадре; это не два независимых рандомных эффекта.
15. **Цвет — дополнительная подсказка.** Если направление времени обозначается цветом, **только из канонической палитры Kira**; красно-синяя гамма фильма не импортируется. Различимость не должна зависеть только от цвета.
16. **Предопределённость без обмана.** Декоративные следы могут появляться на hover *до* нажатия, но навигация, запуск приложения, изменение даты, копирование и другие реальные действия выполняются **только после подлинного события**.

## II. Технический контракт

### Направление и общий ход времени

Для сцены с длительностью `D` и нормализованным временем `u = clamp(t/D, 0, 1)`:

```text
FORWARD:  localProgress = u
INVERTED: localProgress = 1 - u
```

Это **индекс по сохранённой истории**, а не готовая физическая модель. Если записанная траектория `P(u)` включает easing и отскоки, обратная траектория равна `P(1 - u)`, а не «то же easing на координатах с минусом». Для монотонной функции easing `E` инвертированный профиль изменения `1 − E(1 − u)` демонстрирует обратное ускорение/замедление. Для составных сцен нужно воспроизводить историю keyframes/timeline целиком.

Сцена описывает **единый** временной курсор и отдельные объекты с направлением, начальными/конечными состояниями, записанной последовательностью событий и точкой синхронизации. **В момент переключения нельзя регенерировать случайные пути**. Новое независимое нажатие может создать новую траекторию, но возврат *внутри этого нажатия* использует сохранённые параметры.

### Стек и жизненный цикл

- **GSAP** остаётся единственным JS-движком motion. Использовать `gsap.timeline()`, `reverse()`/`reversed()` или явные сохранённые keyframes, а не добавлять другие анимационные библиотеки или переписывать эффекты CSS-кейфреймами.
- Для одновременных FORWARD/INVERTED слоёв использовать **один master timeline / общий момент контакта**, сохраняя локальное направление отдельных слоёв. Инверсия всей страницы не допускается.
- **Apache ECharts** остаётся единственным движком графиков. Временные эффекты не должны изменять данные CPU/RAM/GPU, метки времени, оси или реальную частоту сэмплов. Инверсия допустима **только для декоративной анимации**, не для представления измеренных фактов.
- Предпочитать `transform` и `opacity`; избегать дорогостоящего layout/paint, бесконечных циклов, сетевых ресурсов и WebGL в компактном WebKitGTK-поповере.
- **На открытии** — инициализировать эффект для текущего экземпляра виджета; **на повторном клике** — остановить/перезапустить или корректно реверсировать; **при закрытии/смене вкладки** — убить tweens/timelines, таймеры и наблюдатели, очистить декоративные элементы и восстановить DOM.
- Всегда поддерживать `prefers-reduced-motion: reduce`: мгновенное достоверное конечное состояние, без принудительного «видео назад». Сохранять клавиатурный фокус, читаемые подписи, ARIA и доступное действие без анимации.
- Анимация не должна удерживать кнопку от нажатия, задерживать реальный ответ, стирать введённые данные, блокировать Escape или делать скрытое содержимое недоступным.
- **Без сторонних CDN**: весь GSAP/ECharts код входит в один локальный автономный HTML для WebKitGTK; палитра Kira и 42px Top Bar неизменны.

### Состояния жизненного цикла события

```text
IDLE -> PREPARED -> FORWARD / INVERTED / DUAL -> CONTACT -> SETTLED
                    |                                   |
                    +---- interrupted/cancel ----------> RESET
```

`PREPARED` запоминает исходную геометрию и параметры. `CONTACT` — общая точка потоков. `SETTLED` и `RESET` возвращают корректные transform, opacity и доступность, без «полузастрявших» фрагментов. При независимом следующем взаимодействии можно заново выбрать random seed; **в пределах одного события он неизменен**.

## III. Сценарии виджетов

| Поверхность | Обычное время | TENET-момент |
| --- | --- | --- |
| Кнопка | Фокус, hover и click доступны сразу | Световой след появляется до контакта и сжимается к реальной точке активации |
| Calendar / часы | Настоящее время и даты не останавливаются | Цифры разлетаются по сохранённым траекториям и возвращаются **по этим же путям**; следы собираются обратно |
| Calendar / выбор дня | Дата и выделение меняются в ответ на действие | Следы выбранного дня сходятся в точке выбора, не задерживая фактическое обновление |
| Launcher | Поиск, навигация и запуск работают сразу | Частицы собираются в результат или уходят обратно в историю появления без подмены выборки |
| System Monitor | CPU/RAM/GPU остаются правдивыми и синхронными | Декоративная сборка рамок/типографики, но **не** обратная прокрутка реальных метрик |
| Карточка / модальное окно | Функция открывается/закрывается корректно | При закрытии элементы точно восстанавливают маршрут появления, включая вторичные следы |
| Галерея / переключение | Новое содержимое действительно выбирается | Уходящий слой движется FORWARD, новый INVERTED к точке контакта |
| Текст / загрузка | Текст и состояние доступны постоянно | Символы и декоративные фрагменты собираются в конечную строку; реальная загрузка не притворяется завершённой |
| Hover / scroll | Прокрутка и фокус остаются нативными | Декоративный след предвосхищает/восстанавливает движение, не нарушая координаты попадания |

### Временные ориентиры, а не лимиты

| Тип | Рекомендуемая длительность |
| --- | --- |
| Hover / отклик кнопки | 150–350 мс |
| Восстановление карточки | 400–800 мс |
| Совместный FORWARD + INVERTED | 700–1200 мс |
| Необязательная кинематографическая сцена | 1200–2000 мс |

Длинный декоративный эффект нельзя навязывать при каждом обычном действии; дополнительные сцены должны быть редкими, легко прерываемыми и ненавязчивыми.

## Наведение мыши: без принудительной деформации

Эксперимент с оптической линзой, SVG `feDisplacementMap` и
преломлением кнопок **отменён по результатам визуальной оценки**.
Он не является частью обязательного TENET Motion System и не должен
автоматически возвращаться в Calendar, System Monitor, Launcher
или будущие виджеты.

Обычные состояния `hover`, `focus-visible` и `disabled`
сохраняются без деформации пикселей и дополнительных слушателей
движения указателя. TENET по-прежнему определяет причинность и
память **других** целенаправленных анимаций, включая календарь и
часы. Новые экспериментальные hover-эффекты требуют отдельного
запроса, визуального утверждения и проверки доступности.

## IV. Критерии приёмки каждой новой анимации

Перед PR разработчик/агент должен ответить на вопросы и **проверить**, а не просто заявить соответствие:

1. **Какие объекты FORWARD, какие INVERTED, где общий контакт?** Если инверсии нет, почему для этой микроанимации достаточно обычного причинного FORWARD?
2. **Какое конкретное состояние/геометрия/траектория записаны?** Обратная часть воспроизводит **те же** события, а не новые случайные координаты?
3. **Что будет при двойном клике, повторном открытии, Escape, unmount, прерывании CSS/GSAP и потере кадров?** Нет зависших transform, осиротевших таймеров/слушателей и фантомных фрагментов?
4. **Можно ли пользоваться виджетом без анимации?** Проверить `prefers-reduced-motion`, фокус, навигацию клавиатурой, доступное имя, реальную функцию и актуальность времени/метрик.
5. **Есть ли одновременно видимые прямой и обратный потоки там, где заявлен DUAL?** Их точка встречи совпадает по времени и координатам?
6. **Проверено ли на настоящем размерах окна?** Написать тесты исходного/конечного состояния, инверсии сохранённого пути, прерывания и cleanup; при возможности проверить реальную сборку в nested Niri/WebKitGTK. Отсутствие ручного визуального QA указать честно.

**Запрещено выдавать** обычный `animation-direction: reverse`, зеркальное смещение, косметический tween, случайное «притяжение» в несвязанный центр, фальшивую телеметрию или стопроцентно инвертированную страницу **за TENET Motion System**.

---

**Нормативный приоритет:** этот документ определяет причинность, время и качество *всех новых/изменяемых анимаций*, [`AGENTS.md`](../AGENTS.md) делает его обязательным для участников и AI-агентов, а [`DESIGN_SYSTEM.md`](DESIGN_SYSTEM.md) сохраняет палитру и общую визуальную иерархию. При конфликте декоративной идеи с доступностью, безопасностью, точностью данных или функциональностью всегда побеждает функциональность.

### Shared overlay entrance · synchronized native + WebKit (2026-11)

Calendar, Launcher и System Monitor используют общий жизненный цикл. Тёплый WebView получает содержимое Svelte и реальную высоту, пока GTK-окно прозрачно. Только после подтверждения mount/paint и проверки поколения `kira:overlay:visible` запускает **одну** короткую композицию: native GTK проявляет уже готовый window за 133 мс (`cubic-out`), GSAP мягко собирает 2–3 передние секции за ~367 мс при общем timeScale(1.2) (9 px, scale 0.988, opacity 0.94; `back.out(1.22)` с монотонным opacity), а четыре заранее определённых инвертированных следа возвращаются в тот же contact point по сохранённым путям и обратному `power3.in`. Тяжёлые графики System Monitor не перемещаются.

Нативное окно **не** масштабируется и не изменяет позицию при reveal. Размер определяется `ResizeObserver` до открытия и не зависит от GSAP transform. Время и реальные данные не тормозятся. Общий event поколения исключает запуск stale WebKit-сцены. Native fade прерывается новым открытием/закрытием и никогда не управляет opacity следующего поколения.

При `prefers-reduced-motion: reduce` Svelte передаёт флаг на Rust через ограниченную команду `mounted:<generation>:<0|1>`, а при смене настройки `motion:<generation>:<0|1>`. Нативное окно становится непрозрачным сразу; GSAP оставляет подлинные стили. Если сигнал видимости не пришёл, содержимое восстанавливается через 550 мс без проигрывания; при throttled WebKit откат срабатывает через 1200 мс. Закрытие, размонтирование и смена настроек убивают tweens, слушатели и следы.

### WebView surface materialization · no rectangular flash (2026-11)

**Появление и исчезновение самого WebView, не только содержимого.** Popup получает CSS-класс `kira-popup-transparent`; GTK4 CssProvider устраняет фон и тени именно **GTK ApplicationWindow** (в том числе серый фон системной темы), а WebKit backing имеет alpha 0. HTML/Body/`#app` для `data-kira-surface="calendar"` также прозрачные. Только семантический непрозрачный `main[data-kira-ui-root]` составляет видимую физическую поверхность. До native `visible` весь `main` скрыт через `clip-path: inset(...100%...)`, а Svelte успевает измерить реальную высоту, отправить resize и подтвердить paint. Никакой чёрной полноразмерной вспышки GTK, и при этом ни пикселя смещения/масштабирования настоящей Wayland-поверхности.

Один master GSAP timeline теперь включает **проявление внешней поверхности за ~450 мс (540/1.2)** с `power3.inOut`, тонкий акцентный световой шов, перемещающийся строго вдоль ведущей границы раскрытия, и прежнюю упругую сборку 2–3 секций + инвертированные следы. Calendar/System раскрываются сверху вниз; Launcher, используя `direction=-1`, снизу вверх. Шов затухает без overshoot яркости; при полном раскрытии маска сохраняется как история, не создавая дополнительных repaint циклов.

**Закрытие** воспроизводит ту же шкалу целиком в обратном направлении: секции уходят, световой шов возвращается по исходной траектории, а непрозрачная поверхность целиком сворачивается обратно в прозрачность. Rust получает `closed:<generation>` только после `onReverseComplete`, затем `hide()` освобождает WebView. Повторное открытие на промежуточном кадре разворачивает эту же поверхность обратно. При reduced motion пропускаются и маска, и шов, при WebKit throttling через существующие ограниченные тайм-ауты выставляется точная крайняя позиция, на unmount GSAP маска и DOM-шов полностью очищаются.

Область действия строго ограничена popup HTML; 42px Top Bar и его фон не изменяются. WebKit-геометрия, привязки Wayland, размер и слой прозрачности GTK не анимируются, поэтому Niri не пересоздаёт окно на каждом кадре.

### Reversible widget dismissal · shared TENET temporal memory (2026-11)

Каждый popup Calendar, Launcher и System Monitor сохраняет **один и тот же** master GSAP timeline появления, включая stagger, `back.out`-пружину, отдельную монотонную прозрачность и четыре фиксированных INVERTED-следа у исходной точки контакта. По `kira:overlay:close` таймлайн воспроизводится **в обратном порядке** через `master.reverse()` из текущего времени, а не заменяется новым exit tween: сначала уходят последние собранные секции, затем предыдущие, а следы разлетаются ровно по исходным, уже сохранённым траекториям. Действительные значения часов/метрик и интерактивные состояния не откатываются.

Нативный Rust хост при этом сохраняет WebView и GTK-окно видимыми и удерживает lease. После `onReverseComplete` WebKit отправляет строго проверенный `closed:<generation>`; только тогда Rust вызывает `hide()`, размонтирует Svelte и освобождает слот. Длительность обратного прогона определяется **сохранённой** временной шкалой (~0.45 с), а не произвольной задержкой Rust. При быстро повторённом нажатии того же открытия `kira:overlay:reopen` вызывает `master.play()` с текущего кадра без скачка и с отменой предыдущего запроса. Запоздавшие ACK отвергаются при несовпадении поколения или флага закрытия.

На закрытии до первого paint или при `prefers-reduced-motion` скрытие мгновенное. При зависании WebKit срабатывает ограниченный native watchdog (1100 мс); после него никакой renderer не остаётся захваченным бесконечно. Действия закрытия через Escape, крестик, Top Bar, успешный запуск приложения и системную команду проходят через один двухфазный контракт. Само скрытие/отмена/destroy уничтожает timeline, созданные следы, таймеры и слушатели. Native opacity остаётся 1 во время обратной GSAP-сцены, а не обрезает её преждевременным fade.

### Continuous selection · System Monitor (2026-11)

Навигация хранит **один** `data-kira-flow-indicator`, а не два активных нижних бордера. `tenetFlowIndicator` измеряет положение и ширину выбранной кнопки, движется через GSAP `back.out(1.18)`, при повторном выборе переназначает цель из текущего положения через `overwrite: 'auto'`. `ResizeObserver` пересчитывает реальные координаты, reduced motion и unmount останавливают tween. `aria-current` и состояние выбранной вкладки меняются сразу; новая панель получает короткое, не мешающее телеметрии появление.


### Continuous motion across built-in widgets · all moving selections (2026-11)

**Тот же инвариант, что у вкладок System Monitor, распространяется на все существующие элементы, которые меняют положение или выбор:**

| Поверхность | Непрерывный объект | Реакция |
| --- | --- | --- |
| Calendar / выбранный день | Один оранжевый фон за реальными кнопками дат | Измеренные `x/y/width/height`, `back.out`, повторное нажатие перенаправляет tween |
| Calendar / смена месяца | Одна поверхность сетки вместо десятков независимо летающих ячеек | Короткое упругое приземление, инвертированные TENET-следы сохраняют записанную историю и контакт |
| Launcher / выбранное приложение | Один общий фон со штрихом слева вместо множества включаемых/выключаемых полос | Переход по обеим осям, реальная прокрутка к выбранной строке |
| Launcher / результаты поиска | Сохранившиеся элементы маленьких списков | GSAP Flip для реального перемещения, но без искусственного пролёта 80 строк при радикальном изменении запроса |
| Top Bar / рабочие пространства Niri | Один общий оранжевый фон, лежащий под физическими кнопками | Переход по реальной геометрии и мягкая горизонтальная прокрутка к новому фокусу, сам фокус меняет только Niri |
| System Monitor / сортировка процессов | Переиспользуемые строки по PID | GSAP Flip только по пользовательской сортировке/фильтру, не на каждом обновлении датчиков |
| System Monitor / раскрытие диагностики | Один контент-блок | Прерываемое раскрытие вместо мгновенного телепорта высоты, корректная семантика `details` |

Общая реализация: `tenetFlowIndicator` (один persistent DOM-маркер), `tenetReflow` (FLIP по stable keys), `tenetScrollIntoView` (прерываемая GSAP-прокрутка), `tenetDisclosure` (управляемый контент), а также существующие `tenetWidgetReveal` и календарные DUAL-сцены. Любое изменение на лету начинается от текущей отрисованной позиции и при reduced motion мгновенно становится в точную цель. Все действия и ARIA обновляются до окончания анимации.

**Исключения, которые защищают смысл UI:** измеренные ECharts-линии и шкалы не получают упругие overshoot значений (их факты нельзя «отпружинить» за реальные 100%). Тексты, недоступные датчики, время и изменённый результат поиска могут переключаться дискретно, если между состояниями **нет общей физической сущности**. Не добавлять бесконечное декоративное движение, не оживлять скрытые виджеты, не менять базовую палитру или GTK-геометрию во время entrance.
